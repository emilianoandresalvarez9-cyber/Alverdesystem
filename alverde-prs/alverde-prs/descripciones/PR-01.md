# PR-01 · ci(qa): CI como compuerta real y definición de terminado

**Rama:** `pr-01-ci-puerta-de-calidad` · **Parche:** `patches/PR-01-ci-puerta-de-calidad.patch` · **Depende de:** Ninguno.

## Qué resuelve

El job de base de datos del CI corría `psql -f`, que devuelve 0 aunque pgTAP no esté instalado o un test falle: nunca podía ponerse rojo (verificado). Además había 3 tests `expect(true).toBe(true)` contados como aprobados (CRÍTICO-02).

## Cambios

- Job `database`: `supabase db start` + `supabase test db` con la CLI fijada en 2.117.0.
- Job `migrations`: falla si un PR edita, renombra o borra una migración existente.
- `npm run qa:guard`: bloquea aserciones constantes, `.only`, casos sin `expect`, tests SQL sin `plan/finish` y mocks nuevos en `src/` (lista `qa/mocks-conocidos.txt` que solo se achica).
- Tests falsos reemplazados por `it.todo` visibles.
- `AGENTS.md` reescrito (definición de terminado, prohibiciones) y plantilla de PR.
- Arnés `qa/pg-harness` para correr migraciones y pgTAP sin Docker.

## Cómo se verificó

- `npm run verify` (guard, tipos, tests, build) y `npm run test:db:nodocker` (migraciones + pgTAP sobre PostgreSQL 16): en verde en este commit.
- Se probó que `check-migrations-immutable.sh` falla al editar una migración y que `qa:guard` falla con un mock nuevo y con las aserciones vacías.
- Vitest: 26 aprobados + 3 pendientes (antes: 29 "aprobados").

## Para quien revise

**Primera corrida real de `supabase test db` en GitHub (T-04).** No pude ejecutarla fuera de este entorno. Si el job falla con `function plan(integer) does not exist`, la CLI no habilitó pgTAP: corregilo en un commit nuevo de este mismo PR (por ejemplo, un paso `supabase db query "create extension if not exists pgtap with schema extensions"` antes de `supabase test db`) y no desactives el job.
